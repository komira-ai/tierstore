Early development open source, Apache 2.0

A hot tier in front of a cold store, behind one S3 endpoint.

tierstore is an S3 server over two S3-compatible stores. It writes new objects to the hot tier, copies them to the cold tier in the background, and frees the hot tier when it fills. Clients see one bucket and sign with any S3 SDK.

Install works today Linux and macOS, from a GitHub release

$ tar -xzf tierstore-<commit>-linux-x86_64.tar.gz tierstore

tierstore ships from its own GitHub releases: each release carries its tarball. Get started has the steps, including how to verify the download.

What it does

Two tiers, one bucket

  • Writes land on the hot tier

    On a store on the entry format a put is refused if the key exists in either tier; on the marker format a plain put replaces it. It is written to the hot tier and acknowledged once its entry (or marker) says it landed there.

  • The cold tier is filled in the background

    One reconciler at a time, guarded by a lease object in the hot tier, copies puts to the cold tier and never scans either tier's data.

  • The hot tier is freed when it fills

    Above the high-water mark it evicts the oldest objects that the cold tier already holds, down to the low-water mark.

  • Reads try hot, then cold

    A cold hit is copied back into the hot tier. A listing merges both tiers.

The why page says what problem this solves and where it stops; configuration and operations are the reference.
