Get started

tierstore is an S3-compatible object store over a fast hot tier and a large cold tier, with a read-only OCI registry front and a disk cache for build nodes. This page runs one process on one machine with two directories as the tiers, and puts and gets an object. It takes about five minutes.

  1. Download and verify

    Take the tarball of your platform (linux-x86_64, linux-arm64 or macos-arm64) and SHA256SUMS from the same release.

    $ gh release download --repo komira-ai/tierstore \
    --pattern 'tierstore-*-linux-x86_64.tar.gz' --pattern SHA256SUMS
$ sha256sum -c --ignore-missing SHA256SUMS
$ tar -xzf tierstore-*-linux-x86_64.tar.gz tierstore
$ ./tierstore --version

    The checksum proves the download is intact. To prove that this repository built and signed it, run a check from the install page.

  2. Write a key file and a configuration file

    A key file is the access key id and then the secret, one on each line. It must not be readable by group or others.

    $ printf 'AKIDEXAMPLE\nexample-secret-change-me\n' > access.key
$ chmod 0600 access.key
$ mkdir hot cold

    Write tierstore.toml in the same directory:

    [server]
listen          = "127.0.0.1:9000"
proxy_id        = "tierstore-1"
bucket          = "tierstore"
access_key_file = "access.key"

[hot_store]
kind   = "dir"
path   = "hot"
budget = "1GiB"

[cold_store]
kind = "dir"
path = "cold"

  3. Start it

    $ ./tierstore --config tierstore.toml

    The process asks each tier the questions its guarantees rest on, then prints its version and the address it listens on. curl http://127.0.0.1:9000/readyz answers ready. Stop it with Ctrl-C: it drains and exits.

  4. Put and get an object

    The front serves one bucket, path-style, over plain HTTP, and refuses the checksum trailer that recent AWS clients send by default, so tell the aws CLI to send checksums only when required.

    $ export AWS_ACCESS_KEY_ID=AKIDEXAMPLE AWS_SECRET_ACCESS_KEY=example-secret-change-me AWS_DEFAULT_REGION=us-east-1
$ aws configure set default.s3.addressing_style path
$ aws configure set default.request_checksum_calculation when_required
$ aws configure set default.response_checksum_validation when_required
$ echo hello > hello.txt
$ aws --endpoint-url http://127.0.0.1:9000 s3api put-object --bucket tierstore --key hello.txt --body hello.txt
$ aws --endpoint-url http://127.0.0.1:9000 s3api get-object --bucket tierstore --key hello.txt out.txt
$ cat out.txt

    A put is create-only: putting hello.txt again is refused with 412. tierstore's own tests drive the front with an SDK set this way, not with the aws CLI.

The three configurations

Every configuration is one process started with --config <file>. The file has the tables of the role the process plays; the configuration reference lists every key and its default.

Storage node

A hot tier on SSD in front of a cold tier on spinning disks, with a read-only key for daemons that only read. Either tier may instead be kind = "s3" with a bucket, an endpoint and a credentials_file. An [oci] table with a listen address adds the read-only OCI registry front.

[server]
listen              = "192.0.2.10:9000"
proxy_id            = "tierstore-1"
bucket              = "tierstore"
access_key_file     = "/etc/tierstore/access.key"
read_only_key_files = ["/etc/tierstore/daemons.key"]

[hot_store]
kind   = "dir"
path   = "/srv/tierstore/hot"
budget = "800GiB"

[cold_store]
kind = "dir"
path = "/srv/tierstore/cold"

Build node

A read cache on local disk in front of one upstream, with no hot tier. The upstream is [cold_store], read with a read-only key, and [[policy]] says which key prefixes are kept.

[server]
listen          = "127.0.0.1:9400"
proxy_id        = "tierstore-cache-1"
bucket          = "tierstore"
access_key_file = "/etc/tierstore-cache/access.key"

[local_cache]
path   = "/var/lib/tierstore-cache"
budget = "40GiB"

[cold_store]
kind             = "s3"
bucket           = "tierstore"
endpoint         = "http://s3-cold.example:9000"
credentials_file = "/etc/tierstore-cache/upstream-read.key"

[[policy]]
prefix = "cas/b/"
cache  = true

All-in-one not in a release yet

One process that is both: the storage node's two tiers and the build node's disk cache in front of them, for a single machine. It has no configuration keys yet.
