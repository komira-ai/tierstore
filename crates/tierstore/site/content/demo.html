Demo

A start, the three probes and a drain, on one machine with two directories as the tiers. There is no recording to replay: every line below is the text the program prints, read from its source, and each block says where.

What is not shown. Writing and reading objects is not in this transcript, because the repository has no recorded session of it to quote. The Get started page has the client settings, and the crate's tests put, get, range-read, list, delete and upload in parts through an SDK. A <placeholder> below stands for a value the process prints that differs on every run.

1. Start it

The key file is the two-line form: the access key id, then the secret. A tier may be a directory, which needs no second store.

$ printf 'AKIDEXAMPLE\nthe secret\n' > access.key
$ chmod 0600 access.key
$ cat tierstore.toml
[[interface]]
type   = "s3"
params = { addresses = ["127.0.0.1:9000"] }

[server]
proxy_id        = "tierstore-1"
bucket          = "tierstore"
access_key_file = "access.key"

[hot_store]
kind   = "dir"
path   = "hot"
budget = "1GiB"

[cold_store]
kind = "dir"
path = "cold"
$ tierstore --config tierstore.toml
tierstore <version> listen=127.0.0.1:9000

The file is the one of the configuration; the process takes no flag for it. The line is written to stdout by the binary (crates/tierstore/src/server/cli.rs). The process does not test or probe its tiers; see what tierstore requires of a store.

2. The probes

$ curl -s http://127.0.0.1:9000/healthz
ok
$ curl -s http://127.0.0.1:9000/readyz
ready
$ curl -s http://127.0.0.1:9000/usagez
no usage yet, <N>s since start

The bodies of /healthz and /readyz are strings of crates/tierstore/src/server/mod.rs; the bodies of /usagez are those of crates/tierstore/src/server/usage_probe.rs. The probes are not signed. Once the reconciler has published the hot tier's usage, /usagez says usage published <N>s ago; if that usage goes stale it answers 503 with the reason. See operations.

3. Stop it: the drain

On SIGTERM or SIGINT the process drains. /readyz answers 503 at once while the server keeps serving for --drain-lb-wait, so a load balancer sees it; every answer from then on carries Connection: close; at the end of that wait it stops accepting connections and closes each idle connection with a lingering close (it shuts its end for writing and reads until the client closes, for at most the header timeout, 60 seconds by default), and a request already on the wire is served, not answered 503. It then waits for the requests in flight and the connections to close (at most --drain-deadline), gives up the reconciler's lease and exits 0.

$ kill -TERM <pid of tierstore>
$ curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9000/readyz
503
$ curl -s http://127.0.0.1:9000/readyz
draining

Both requests are made inside the --drain-lb-wait window (give the flag a few seconds to try this). The status and the body are those of /readyz in server/mod.rs; the exit status 0 is documented in server/cli.rs and packaging/README.md, "Stopping it".

4. The flags that went

The process takes only --config for its data path. A flag that an earlier build took for it is refused at the start, with exit status 2 and the key of the file that replaces it:

$ tierstore --listen 127.0.0.1:9000 --config tierstore.toml
tierstore: --listen was removed: the file given with --config holds it; declare an [[interface]] with type = "s3" and params port or addresses

The message is built by removed in crates/tierstore/src/server/config.rs.
