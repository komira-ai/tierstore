Demo

A start, the three probes and a drain, on one machine with two directories as the tiers. There is no recording to replay: every line below is the text the program prints, read from its source, and each block says where.

What is not shown. Writing and reading objects is not in this transcript, because the repository has no recorded session of it to quote. The install page has the client settings, and the crate's tests put, get, range-read, list, delete and upload in parts through an SDK. A <placeholder> below stands for a value the process prints that differs on every run.

1. Start it

The key file is the two-line form: the access key id, then the secret. A tier may be a directory, which needs no second store.

$ printf 'AKIDEXAMPLE\nthe secret\n' > access.key
$ chmod 0600 access.key
$ tierstore --listen 127.0.0.1:9000 --proxy-id tierstore-1 --bucket tierstore \
    --access-key-file access.key \
    --hot dir:./hot --cold dir:./cold --hot-bytes 1073741824
tierstore: testing the hot tier dir:./hot
tierstore: tested the hot tier dir:./hot in <N> ms
tierstore: testing the cold tier dir:./cold
tierstore: tested the cold tier dir:./cold in <N> ms
tierstore <version> listen=127.0.0.1:9000

The flags are those of the example unit and --help. The first four lines are written to stderr by probe_tiers and the last to stdout by the binary (crates/tierstore/src/server/cli.rs). Before it binds the address, the process asks each tier the questions its guarantees rest on; see the start-up self-test.

2. The probes

$ curl -s http://127.0.0.1:9000/healthz
ok
$ curl -s http://127.0.0.1:9000/readyz
ready
$ curl -s http://127.0.0.1:9000/usagez
no usage yet, <N>s since start

The bodies are the strings of crates/tierstore/src/server/mod.rs. The probes are not signed. Once the reconciler has published the hot tier's usage, /usagez says usage published <N>s ago; if that usage goes stale it answers 503 with the reason. See operations.

3. Stop it: the drain

On SIGTERM or SIGINT the process drains. /readyz answers 503 at once while the server keeps serving for --drain-lb-wait, so a load balancer sees it; every answer from then on carries Connection: close; at the end of that wait it stops accepting connections and closes each idle connection with a lingering close (it shuts its end for writing and reads until the client closes), and a request already on the wire is served, not answered 503. It then waits for the requests in flight and the connections to close (at most --drain-deadline), gives up the reconciler's lease and exits 0.

$ kill -TERM <pid of tierstore>
$ curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9000/readyz
503
$ curl -s http://127.0.0.1:9000/readyz
draining

Both requests are made inside the --drain-lb-wait window (give the flag a few seconds to try this). The status and the body are those of /readyz in server/mod.rs; the exit status 0 is documented in server/cli.rs and packaging/tierstore/README.md, "Stopping it".

4. From flags to a file v0.0.39 and later

This step needs v0.0.39 or later. --print-config and --config are not in v0.0.38 or earlier. Steps 1 to 3 use flags only and work with any release.

--print-config, given the flags of a start, prints the TOML file that is equivalent and exits 0 without starting anything. It names key files by path and never prints what is in them.

$ tierstore --print-config --listen 127.0.0.1:9000 --proxy-id tierstore-1 --bucket tierstore \
    --access-key-file access.key --hot dir:./hot --cold dir:./cold --hot-bytes 1073741824
# The configuration file equivalent to the flags that `tierstore --print-config` was given.
# Start the server with `tierstore --config <this file>` and without the flags it replaces;
# only --drain-lb-wait and --drain-deadline stay flags. The key files are named by path.

(the file follows: the tables [server], [hot_store] and [cold_store], as on the configuration page)

The three comment lines are the header constant of server/config_print.rs; the last line is this page's summary of the rest, not program output. A test loads the printed file back and checks it makes the settings the flags made.
