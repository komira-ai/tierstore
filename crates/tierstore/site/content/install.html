Install

Take the tarball, which works today. The other ways are written and arrive with the next release.

One block for Linux (x86_64 or arm64) and macOS (Apple silicon). It takes the tarball of the machine it runs on from the latest release on GitHub, with its signature bundle and SHA256SUMS for the checks below, unpacks it and prints the version.

$ os=$(uname -s | sed 's/Darwin/macos/; s/Linux/linux/')
$ arch=$(uname -m | sed 's/aarch64/arm64/')
$ gh release download --repo komira-ai/tierstore \
    --pattern "tierstore-*-$os-$arch.tar.gz*" --pattern SHA256SUMS
$ tar -xzf tierstore-*-$os-$arch.tar.gz tierstore
$ ./tierstore --version

No gh? Take the same files from the releases page. The last line is the check that it runs: it prints a version.

Not in a release yet. The package tierstore is in the repository packages.komira.ai. The block fetches the repository's key, trusts it for this source only (Signed-By), and installs. Until a release has it, use the Tarball tab.

sudo install -d -m 0755 /usr/share/keyrings
sudo curl -fsSL https://packages.komira.ai/apt/komira-archive-keyring.gpg -o /usr/share/keyrings/komira-archive-keyring.gpg
sudo tee /etc/apt/sources.list.d/komira.sources >/dev/null <<'EOF'
Types: deb
URIs: https://packages.komira.ai/apt
Suites: stable
Components: main
Signed-By: /usr/share/keyrings/komira-archive-keyring.gpg
EOF
sudo apt update
sudo apt install tierstore
tierstore --version

apt checks the package against the key named in Signed-By. The last line is the check that it runs: it prints a version.

Verify the tarball

This is for the Tarball tab only. The script checks its own download, and Homebrew and apt install from their own repositories. Run these in the directory you downloaded into, in the same shell, so that $os and $arch are still set.

Check it

The first line proves the file is intact. The second proves a workflow of this repository built it.

$ sha256sum -c --ignore-missing SHA256SUMS
$ gh attestation verify tierstore-*-$os-$arch.tar.gz --repo komira-ai/tierstore

More ways

For a stricter check, without gh, or on a host with no network. <commit> is the full commit SHA in the tarball's name, and <tarball> is the tarball's file name, tierstore-<commit>-linux-x86_64.tar.gz for instance.

Integrity

The checksum file lists every platform's tarball, so --ignore-missing skips the ones you did not take. It proves the file is intact, not who built it.

Authenticity with gh, pinned to the workflow and the commit

This also proves the build ran the workflow artifacts.yml on main from that commit.

gh attestation verify tierstore-<commit>-linux-x86_64.tar.gz --repo komira-ai/tierstore \
  --signer-workflow komira-ai/tierstore/.github/workflows/artifacts.yml \
  --source-ref refs/heads/main --source-digest <commit> --deny-self-hosted-runners

Authenticity without gh

This needs only cosign. It prints Verified OK. --type slsaprovenance1 is required: without it cosign fails with "invalid predicate type".

cosign verify-blob-attestation \
  --bundle <tarball>.sigstore.json \
  --type slsaprovenance1 \
  --certificate-identity-regexp '^https://github.com/komira-ai/tierstore/\.github/workflows/artifacts\.yml@refs/heads/main$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  <tarball>

On a host with no network

Fetch the trusted root on a host that has a network, copy it over with the tarball and its bundle, and verify against the bundle.

gh attestation trusted-root > trusted_root.jsonl
gh attestation verify <tarball> --repo komira-ai/tierstore \
  --bundle <tarball>.sigstore.json --custom-trusted-root trusted_root.jsonl \
  --signer-workflow komira-ai/tierstore/.github/workflows/artifacts.yml \
  --source-ref refs/heads/main --source-digest <commit> --deny-self-hosted-runners

Every pinned check names one signer: the workflow .github/workflows/artifacts.yml of this repository, run on refs/heads/main. The binary for macOS is ad-hoc signed and not notarized; gh release download and curl save it without the quarantine attribute, so it runs.
